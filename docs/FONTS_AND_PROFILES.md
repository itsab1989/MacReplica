# Fonts and ICC profiles: selection and conflict policy

MacReplica handles fonts and ICC color profiles in **two independent selection stages**:

1. **On the old Mac – “What do you want to take with you?”**
   Every font and profile found in `~/Library` and `/Library` is listed individually (name, style,
   version, format, file name, size, profile class and color space), grouped by origin, with
   *All/None* per group. The backup contains exactly the selected files that could be copied; files
   that could not be read are listed in `backup_issues`. The manifest records the selection
   (`backup_selection`: found vs. selected) and, per file, its identity (`font` / `profile`),
   `origin`, checksum, size and original path.
2. **On the new Mac – “What do you want to put onto this Mac?”**
   When a backup is opened, MacReplica checks every backed-up item against the destination
   (read-only) and pre-selects everything that was backed up and can be restored safely. The user
   can deselect any item, change decisions per item, and only items that are in the backup can
   ever be selected. Choices are saved in the restore session, survive a restart, and can be
   reviewed before an interrupted restore continues (finished steps keep their results and are
   not repeated).

The same decision logic (`FileConflictAnalyzer`) drives the restore selection, the dry run, the
restore itself and the reports, so the preview always matches what happens.

## Evidence

The policy is based on documentation and on read-only tests on a current Mac (macOS 27 developer
build, SIP enabled). Labels: **[DOC]** documented, **[TEST]** tested locally, **[INF]** inferred.

| Fact | Source |
|---|---|
| `/System/Library/Fonts`, `/System/Library/ColorSync/Profiles` and `/System/Library/AssetsV2` are on the sealed, read-only system volume and protected by SIP. | [DOC] [System Integrity Protection](https://support.apple.com/en-us/102149), [Signed system volume](https://support.apple.com/guide/security/signed-system-volume-security-secd698747c9/web); [TEST] not writable |
| ColorSync domains: User (`~/Library/ColorSync/Profiles`) “for user custom profiles”, Computer (`/Library/ColorSync/Profiles`) shared by all users and normally requiring administrator rights, System for Apple’s profiles. | [DOC] ColorSync SDK header `ColorSyncProfile.h`; [ColorSync](https://developer.apple.com/documentation/colorsync); X-Rite [profile locations](https://www.xrite.com/service-support/icc_profile_locations_on_mac_and_pc_operating_systems) |
| ColorSync has **no precedence order** between profile folders and does not de-duplicate: identical files or profiles with the same description in two folders are listed twice. | [TEST]; ICC.1:2022 §9.2.43: the description “has no fixed relationship to the actual profile disk file name” ([ICC.1:2022](https://www.color.org/specification/ICC.1-2022-05.pdf)) |
| Opening a byte-identical copy of a system profile with `ColorSyncProfileCreateWithURL` returns the **system** profile; the macOS 26.1 SDK adds `kColorSyncDoNotSubstituteProfiles` to turn that off. Copying Apple’s profiles to another folder is therefore pointless at best and a stale duplicate at worst. | [TEST], [DOC] SDK header |
| The ICC Profile ID (header bytes 84–99) is the MD5 of the whole profile with the flags (44–47), rendering intent (64–67) and Profile ID fields set to zero. Many profiles, including all of Apple’s on the test Mac, leave the stored field empty. | [DOC] ICC.1:2022 §7.2.18; [TEST] |
| Display profiles in `/Library/ColorSync/Profiles/Displays/<name>-<UUID>.icc` are generated by macOS per display and per Mac. | [TEST] naming and ownership; [INF] |
| A calibration profile is only accurate for the display it was measured on; Apple’s Display Calibrator assigns new profiles itself. | [DOC] [Display Calibrator Assistant](https://support.apple.com/guide/mac-help/calibrate-mac-display-calibrator-assistant-mchlp1109/mac); [INF] |
| Printer-driver profiles under `/Library/Printers/…` are not listed by ColorSync unless linked from a domain folder; they come back with the driver. | [TEST] |
| No registration is needed: ColorSync scans the domain folders. `ColorSyncProfileInstall` requires a special entitlement. `ColorSyncProfileVerify` returns true “if the profile can be used”. | [DOC] SDK header |
| Font domains in order of precedence: user, local (`/Library/Fonts`, administrator rights), network, system (“should not be altered”); duplicates are resolved by that order. A user copy of a system font therefore takes precedence over macOS’s own. | [DOC] [Font domains (archive)](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/ATS_Concepts/atsfonts_concepts/atsfonts_concepts.html); [TEST] `CTFontCreateWithName` resolved to the user copy |
| Font Book checks for duplicates on install and offers *Resolve Duplicates*. “Legacy suitcase TrueType fonts and PostScript Type 1 LWFN fonts might work but aren’t recommended.” | [DOC] [Font Book: install and validate fonts](https://support.apple.com/guide/font-book/install-and-validate-fonts-fntbk1000/mac) |
| Downloadable system fonts are managed by macOS (MobileAsset) and are downloaded, not copied. | [DOC] [Fonts included with macOS](https://support.apple.com/en-us/122869) |
| `CTFontManagerCreateFontDescriptorsFromURL` parses a font file without installing or activating it (returns no descriptors for invalid files). | [DOC] `CTFontManager.h`; [TEST] |
| PostScript name (name ID 6) identifies a face; the version string is name ID 5. File names are not identity (one `.ttc` holds several faces). | [DOC] [OpenType `name` table](https://learn.microsoft.com/en-us/typography/opentype/spec/name); [TEST] |
| A third-party report says reading resource-fork fonts can crash some macOS 26 versions. | Secondary source, unverified ([Typeface](https://typefaceapp.com/help/tips/postscript)); MacReplica therefore never opens resource-fork fonts |

## Policy

General rules: MacReplica never writes into `/System`, never overwrites a different file without a
decision, never treats a file name or description as proof that two files are the same, and
restores into the same domain (user or shared) the file came from. A replaced file is moved to
`~/Library/Application Support/MacReplica/Replaced Files/<session>/`, never deleted.

Checks run in this order for every backed-up file:

| # | Situation | Status | Default | Choices |
|---|---|---|---|---|
| 1 | The exact same bytes exist anywhere on this Mac (same or other name, user, shared or macOS folder) | `identical` – already present | nothing copied, no duplicate | – |
| 2 | Profile generated by macOS for a display of the old Mac (`Displays/`) | `displayProfile` | never restored; not even pre-selected for the backup | – |
| 3 | macOS on this Mac cannot read the file (Core Text / ICC header) | `incompatible` | not restorable | – |
| 4 | Font whose PostScript name macOS itself provides (`/System/Library/Fonts`, downloadable fonts) | `providedByMacOS` | macOS’s version is used | *Also install backup copy* (into the user’s own folder) |
| 5 | Font: same PostScript names and version under another name or in another form | `equivalent` | nothing copied | – |
| 6 | Font: same PostScript names, different version | `differentVersion` | keep this Mac’s version (two versions must not be active at the same time) | Replace with backup (only a file in the same folder is moved aside), Skip |
| 7 | Font: same file name, different font | `differentFile` | **Keep both**: the backup copy is installed as `Name (MacReplica).ext` | Keep this Mac’s file, Replace, Skip |
| 8 | Profile with the same computed Profile ID (content equal apart from flags/intent) | `equivalent` | nothing copied | – |
| 9 | Profile describing the same thing as one macOS ships (description, class, color space) | `providedByMacOS` | macOS’s version is used | *Also install backup copy* |
| 10 | Profile: same file name, different content | `differentVersion` / `differentFile` | **Keep both** under a new name | Keep this Mac’s file, Replace, Skip |
| 11 | Apple-made profile (`appl`) this macOS no longer ships | `obsoleteAppleProfile` | not pre-selected | select to restore |
| 12 | Profile with the same description under another name | `differentVersion` + advisory “apps will list two entries” | Keep both | Keep this Mac’s, Replace (same folder only), Skip |
| 13 | Classic suitcase or PostScript Type 1 font | `legacyFormat` | not pre-selected, never opened; identical only if data and resource fork match | select to restore |
| 14 | Not on this Mac | `ready` | restored | – |

Custom display calibration profiles are restored as files like any other profile. Which display
used which profile is a separate, optional item (next section).

## Display profile assignments

What macOS offers: the profile a display uses is a per-user ColorSync setting (System Settings ›
Displays › Color profile), readable and settable with the public ColorSync device API
(`ColorSyncDeviceCopyDeviceInfo`, `ColorSyncDeviceSetCustomProfiles`, user scope). Displays are
identified by ColorSync's device ID, which macOS derives from the display (the same value as
`CGDisplayCreateUUIDFromDisplayID`); the built-in display only exists on its own Mac. Profiles macOS
generates for a display (`Displays/`) are recreated by macOS and never restored.

| Step | What MacReplica does |
|---|---|
| Backup | For every display ColorSync knows (connected or not) whose profile the user chose: records the display (salted SHA-256 of its device ID, its name, built-in or not) and the profile — a profile file that is part of the backup (by checksum) or a profile macOS ships (by path). Factory assignments are not recorded. The Mac's hardware UUID is stored only as a salted hash, so the backup can recognise *the same Mac* without containing the identifier. Offered as *Keep N display profile assignments* (selected). |
| Restore, display connected | The profile is restored first (normal file rules), then assigned to the same display in the current user's settings and **read back**; only a matching read-back counts as success. Already assigned → nothing changes. |
| Display not connected | Waits (shown as a guided step); assigned when the restore continues with the display connected, or by the user in System Settings. |
| Built-in display, different Mac | Skipped: that display belongs to the old Mac. Same Mac (salted hardware key matches) → assigned. |
| Profile not available | Skipped with an explanation. |

Verification status: same-Mac reinstall and different-Mac scenarios were run in the real app against
the simulated ColorSync stand-in (scenarios B and C, see [VALIDATION_REPORT.md](VALIDATION_REPORT.md)).
On the development Mac, the live reader found the user's own calibrated profile on the built-in display
and recorded it, and re-assigning that profile through the live API was read back correctly. Assigning
a *different* profile and external displays were not exercised on real hardware.

## Verification

A restored file counts as restored only if

- its SHA-256 matches the manifest,
- fonts: Core Text can read it (`CTFontManagerCreateFontDescriptorsFromURL`); legacy formats are
  checked by checksum only, and
- profiles: the header parses and `ColorSyncProfileCreateWithURL` + `ColorSyncProfileVerify`
  accept it.

Fonts in `~/Library/Fonts` are activated by macOS without registration; apps that are already
running may need to be reopened.

## Logging

Each font and profile gets a language-independent decision code in the restore log and report:
`restored`, `identical_existing`, `equivalent_existing`, `kept_macos_version`,
`conflict_kept_destination`, `conflict_restored_backup`, `conflict_kept_both`, `skipped_by_user`,
`incompatible`, `manual_action_required`, `failed`. Only item identifiers (e.g.
`font:user/Example.otf`) are logged, never file contents.

## Known limitations

- The macOS-provided check compares against the destination’s `/System/Library/Fonts`,
  `/System/Library/ColorSync/Profiles` and downloaded font assets. Fonts inside private system
  frameworks are not inspected.
- Profiles referenced by printer drivers or by application aliases (e.g. Adobe’s folder linked into
  `/Library/ColorSync/Profiles`) are not copied; reinstalling the driver or app brings them back.
- Font activation by running apps cannot be verified without relaunching them.
- Two versions of a font in *different* folders cannot both be avoided without touching a file
  outside the restore folder; MacReplica reports this and leaves the other file alone.
